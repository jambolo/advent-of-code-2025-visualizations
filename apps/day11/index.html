Day 11: Reactor

You hear some loud beeping coming from a hatch in the floor of the factory, so you decide to check it out. Inside, you find several large electrical conduits and a ladder.

Climbing down the ladder, you discover the source of the beeping: a large, toroidal reactor which powers the factory above. Some Elves here are hurriedly running between the reactor and a nearby server rack, apparently trying to fix something.

One of the Elves notices you and rushes over. "It's a good thing you're here! We just installed a new server rack, but we aren't having any luck getting the reactor to communicate with it!"

The Device Network

Each line in the input gives the name of a device followed by a list of the devices to which its outputs are attached. For example, bbb: ddd eee means that device bbb has two outputs, one leading to device ddd and the other leading to device eee.

Data only ever flows from a device through its outputs; it can't flow backwards. The network forms a Directed Acyclic Graph (DAG).

Part 1

Find every path from you to out.

Answer: 523 paths

Part 2

The Elves have figured out that the problematic data path passes through both dac (digital-to-analog converter) and fft (fast Fourier transform device).

Find all paths from svr (the server rack) to out that visit both dac and fft (in any order).

Example

svr: aaa bbb aaa: fft fft: ccc bbb: tty tty: ccc ccc: ddd eee ddd: hub hub: fff eee: dac dac: fff fff: ggg hhh ggg: out hhh: out

Only 2 paths from svr to out visit both dac and fft:

svr,aaa,fft,ccc,eee,dac,fff,ggg,out svr,aaa,fft,ccc,eee,dac,fff,hhh,out

Answer

Part 2: 517,315,308,154,944 paths

How the Solution Works

Overview

The solver uses a clever segment decomposition strategy. Instead of enumerating all paths (impossible with 517 trillion paths!), it breaks the problem into independent segments and multiplies their path counts.

Key Insight

Since paths must visit both fft and dac, the full path can be split into three segments:

  • Segment 1: svr → first checkpoint
  • Segment 2: First checkpoint → second checkpoint
  • Segment 3: Second checkpoint → out

Determining Order

First, check if paths exist from fft to dac:

  • If yes: paths go svr→fft→dac→out
  • If no: paths go svr→dac→fft→out

Graph Reduction

Before counting each segment, the solver reduces the graph:

  1. Find nodes that only connect to "out" (dead ends for intermediate counting)
  2. Collapse these nodes, replacing references with "out"
  3. Repeat until no more reductions possible

This prevents overcounting paths that exit early.

Recursive Path Counting

For each segment, recursively count paths:

count_paths(from, to): if from has no outputs: return 0 total = 0 for each output of from: if output == to: total += 1 else: total += count_paths(output, to) return total

Final Multiplication

Total valid paths = paths(svr→fft) × paths(fft→dac) × paths(dac→out)

= 3,952 × 1,414,944 × 92,456 = 517,315,308,154,944

Why This Works

The multiplication works because:

  • Every path through segment 1 can combine with every path through segment 2
  • The segments are independent once we fix the checkpoint ordering
  • No path can skip a checkpoint (enforced by graph structure)

Complexity

Instead of O(paths) which is infeasible, the algorithm runs in O(nodes × edges) time by counting rather than enumerating.
