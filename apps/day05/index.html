Day 5: Cafeteria

As the forklifts break through the wall, the Elves are delighted to discover that there was a cafeteria on the other side after all.

You can hear a commotion coming from the kitchen. "At this rate, we won't have any time left to put the wreaths up in the dining hall!" Resolute in your quest, you investigate.

"If only we hadn't switched to the new inventory management system right before Christmas!" another Elf exclaims. You ask what's going on.

The Elves in the kitchen explain the situation: because of their complicated new inventory management system, they can't figure out which of their ingredients are fresh and which are spoiled. When you ask how it works, they give you a copy of their database (your puzzle input).

The database operates on ingredient IDs. It consists of a list of fresh ingredient ID ranges, a blank line, and a list of available ingredient IDs. For example:

The fresh ID ranges are inclusive: the range 3-5 means that ingredient IDs 3, 4, and 5 are all fresh. The ranges can also overlap; an ingredient ID is fresh if it is in any range.

The Elves are trying to determine which of the available ingredient IDs are fresh. In this example:

  • Ingredient ID 1 is spoiled because it does not fall into any range.
  • Ingredient ID 5 is fresh because it falls into range 3-5.
  • Ingredient ID 8 is spoiled.
  • Ingredient ID 11 is fresh because it falls into range 10-14.
  • Ingredient ID 17 is fresh because it falls into range 16-20 as well as range 12-18.
  • Ingredient ID 32 is spoiled.

So, in this example, 3 of the available ingredient IDs are fresh.

Process the database file again. How many ingredient IDs are considered to be fresh according to the fresh ingredient ID ranges?

Part 2 Answer: 353,716,783,056,994

How the Solver Works

The solver uses a range-merging algorithm to count all unique fresh ingredient IDs without enumerating them individually (which would be impossible given the trillions of IDs).

The Algorithm

  1. Parse ranges: Read all 182 fresh ingredient ID ranges from the input.
  2. Sort by start: Arrange ranges in ascending order by their start value.
  3. Merge overlapping ranges: Iterate through sorted ranges. If a range overlaps with or is adjacent to the previous merged range, extend it; otherwise, start a new merged range.
  4. Sum the sizes: Calculate end - start + 1 for each merged range and sum them all.

Why Merging Works

Ranges can overlap. The range 10-14 and 12-18 share IDs 12, 13, and 14. Simply summing range sizes would count these IDs multiple times. Merging produces 10-18, correctly counting each ID once.

What the Visualization Shows

  • Green bars (top): Original ranges displayed on a normalized number line.
  • Blue highlight: Range being added as a new merged segment.
  • Orange highlight: Range merging with the previous segment.
  • Light green bars (bottom): Current merged ranges.
  • Running total: Accumulated count of fresh IDs as merging proceeds.

Scale

The actual ingredient IDs range from about 1 trillion to 562 trillion. The visualization normalizes these to fit on screen while preserving relative positions and proportions. The final answer — 353,716,783,056,994 fresh IDs — represents about 63% of the total ID space covered by the merged ranges.
